C&I Portal

Install & Update Guide

Commercial Department  ·  Version 1.0.1  ·  August 2026

A short guide for everyone using the C&I Portal on Windows. You install it once. After that it keeps itself up to date.

There is no Mac version yet — the Portal is currently Windows only.

Part 1

Part 1 — Installing

Set aside about 5 minutes. There is nothing to install beforehand — the Portal brings everything it needs with it, and it does not need administrator rights.

Step 1 — Download the Portal

  1. 1

    Go to the C&I Portal download page.

  2. 2

    Scroll down to the Assets list.

  3. 3

    Click Eternalgy-CI-Portal-Setup-1.0.1.exe to download it.

    It is about 78 MB, so give it a moment on a slow connection.

Step 2 — Install

Windows
  1. 1

    Open the file you just downloaded.

  2. 2

    If Windows shows a blue "Windows protected your PC" box: click More info, then Run anyway.

    This is normal — Windows shows it for any app it has not seen before.

  3. 3

    Choose where to install it, or just accept the suggested folder, and click Install.

  4. 4

    When it finishes, the Portal opens on its own. You will also find it on your Desktop and in the Start menu as Eternalgy C&I Portal.

Why the warning appears

The installer is not code-signed, so Windows cannot show a publisher name. The warning is about the missing certificate, not about anything found in the file. It will keep appearing on each new version until a code-signing certificate is purchased.

Step 3 — Sign in for the first time

The Portal starts with a single administrator account:

UsernamePassword
adminadmin123
  1. 1

    Type the username and password above, then click Sign in.

    Use the eye icon in the password box if you want to check what you typed.

  2. 2

    You are asked to choose your own password straight away. It must be at least 6 characters. Type it twice and continue.

  3. 3

    You are now in the Portal. Your name appears at the top left, and Sign out sits at the top right of every page.

Do this before anyone else signs in

Change the starting password immediately. Until it is changed, anyone who opens the app on that computer can get in with the details printed above.

Part 2

Part 2 — Adding your colleagues

Only administrators see this. Everyone else gets modules 01 to 08 and works normally — they simply do not see the IT Admin page.

Creating an account

  1. 1

    In the sidebar, under System, click IT Admin.

  2. 2

    Open the Users tab, then click + Add user.

  3. 3

    Fill in their full name, a username, and a starting password.

    Usernames may contain spaces — amirul hakim is fine. Capitals and extra spaces are ignored when signing in.

  4. 4

    Choose a role: User for normal work, or Admin if they should also manage accounts and see the edit log.

  5. 5

    Leave Require a password change at next sign-in ticked, so they pick their own password the first time they open the Portal.

If someone forgets their password

There is no self-service reset. An administrator opens IT Admin → Users, clicks Edit on that person, types a new password, and leaves the "require a password change" box ticked. The person then sets their own password when they next sign in.

Seeing who changed what

IT Admin → Edit log records every change: who made it, when, which module and record, which field, and the value before and after. Sign-ins, failed sign-ins and account changes are listed too.

  • Filter by person, module, action, date range, or free text.
  • Export CSV saves whatever the filters are currently showing.
  • The log keeps the most recent 3,000 entries.
What signing in does and does not do

Sign-in makes the Portal accountable — every change carries a name, and ordinary users cannot reach IT Admin. It is not a security boundary: the whole Portal runs on the local computer, so somebody technical could reach the underlying data directly. Treat it as a record of who did what, not as a lock on the data.

Part 3

Part 3 — Staying up to date

You do not need to download anything again. The Portal checks for a newer version each time it starts.

How an update reaches you

  1. 1

    You open the Portal and work as normal.

  2. 2

    If a newer version exists, it downloads quietly in the background. Nothing interrupts you.

  3. 3

    A dark bar appears at the bottom of the window: "Version 1.0.2 is ready to install."

  4. 4

    Click Restart now when you are at a sensible stopping point. The Portal closes, updates, and reopens.

  5. 5

    Not a good moment? Click ✕ to dismiss the bar. The update installs by itself the next time you close the Portal.

Your data is safe across updates

Updating never touches your records. Clients, deals, materials, reports, users and the edit log all stay exactly as they were.

Checking by hand

To check without waiting for a restart, use File → Check for Updates… in the menu bar. If you are already current, the Portal says so.

You can confirm which version you are running under Help → About.

Part 4

Part 4 — Your data

This is the part most worth reading twice.

Where your records live

Everything you enter is stored on your own computer. There is no server behind the Portal. That has three consequences worth knowing:

  • Two people running the Portal do not see each other's data. Each copy is separate.
  • If that computer is lost or wiped, the data goes with it unless you have a backup.
  • Data entered in the web version at localhost does not appear in the installed app — move it across with a backup file.

Backing up and moving data

  1. 1

    At the bottom of the sidebar, click ⬇ Backup (.json). A file is saved to your Downloads folder, dated with today's date.

  2. 2

    Keep it somewhere safe — a shared drive or OneDrive folder.

  3. 3

    To load it on another computer, open the Portal there and click ⬆ Restore backup.

Handle backup files carefully

A backup contains every record and the user accounts, including scrambled password data. It is not a file to email around casually. Restoring a backup also replaces everything currently in the Portal on that computer — it does not merge.

Get into the habit of taking a backup at the end of each week, and always before restoring one.
